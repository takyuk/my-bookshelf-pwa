My Bookshelf PWA

■ 構成
index.html: 画面の構造
css/styles.css: デザイン
js/validation.js: 書籍データの検証
js/storage.js: localStorageの読み書き・同時保存の保護
js/app.js: 本棚表示・編集・検索・書き出し・復元
js/pwa.js: インストール案内・更新確認
js/version.js: 生成されたコミット情報
sw.js / manifest.webmanifest / icons/: PWAとオフライン表示
scripts/: ローカル起動・公開ファイル生成
tests/: 自動チェック

■ ローカル起動（Node.js）
node scripts/prepare.cjs
node scripts/serve.cjs 8000
http://127.0.0.1:8000/ を開きます。ポート使用中は8001などを指定します。
CSSを分離したため、以前の簡易サーバーではなく上記のサーバーを使用してください。
ローカル表示は基準コミットIDと未コミット変更の有無です。
コード変更やコミット後は prepare.cjs を再実行してください。

■ 保存と同時編集
書籍は従来と同じ my-bookshelf-v1 キーにJSON配列で保存します。
データ形式は変更していません。クラウド同期はありません。
複数画面での保存はWeb Locksで順番に処理し、編集開始時から保存データが
変更されていた場合は保存を止めます。入力は残るので必要な内容を控え、
編集を閉じて最新の本棚でやり直してください。削除・全件読み込みも同じ保護の対象です。
編集中以外は、別画面での変更や画面復帰時に本棚を読み直します。
Web Locksが使えない環境では安全のため保存を停止します。
HTTPSまたはlocalhost/127.0.0.1で、Web Locks対応ブラウザを使ってください。
旧版には同時保存の保護がないため、更新後は旧版のタブを閉じてください。

■ 読み込み失敗と復旧
保存データを読み込めない場合、専用の案内を表示し、蔵書数を「—」にします。
空の本棚として書き出さないよう、通常の書き出しと追加を停止します。
「元データを救出」は保存内容を加工せずTXTでダウンロードします。
救出ファイルは調査・修復用であり、そのまま読み込める正常なバックアップとは限りません。
ブラウザ自体が保存領域へのアクセスを拒否している場合、救出できません。
設定を確認して「再読み込みを試す」を使ってください。
正常なバックアップJSONを「読み込み」で選ぶと、確認後に全件置き換えます。
元データを救出してから復元してください。定期的な通常のJSON書き出しも推奨します。

■ PWA
HTTPS公開またはlocalhostで動作します。file://ではインストールできません。
ページ・CSS・JavaScript・アイコンをキャッシュします。
オンライン時はネットワークを優先し、失敗または約5秒経過でキャッシュを使います。
起動・画面復帰・オンライン復帰・表示中の1時間ごとに更新を確認します。
更新時は再読み込みしますが、編集画面や保存処理の完了を待ちます。

■ GitHub PagesでコミットIDを自動表示する公開方法
.github/workflows/pages.yml に公開ワークフローを用意しています。
今回の作業ではGitHub側の設定変更・commit・pushは行っていません。
導入時にリポジトリの Settings → Pages → Build and deployment の
Source を GitHub Actions に設定してください。
その後、mainへのpushまたはActionsの手動実行で、テスト→生成→公開します。
生成時に公開するコミットIDを埋め込み、キャッシュ名にも同じIDを使います。
公開ファイルはdistにまとめ、ソース側のバージョン表示を公開IDと誤認しないようにします。
ブランチから直接公開する方式では自動埋め込みは行われません。
公式手順: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

公開用生成（コミット済みの作業ツリー専用）:
node scripts/prepare.cjs --publish
未コミットのまま生成結果だけを確認する場合:
node scripts/prepare.cjs --preview
previewには開発版表示が入り、公開版のコミットIDとは区別されます。
distは生成物のためGit管理対象外です。公開時のキャッシュ番号の手動更新は不要です。

■ 自動チェック
node tests/regression.cjs
同時保存、古い画面からの削除・読み込み、保存失敗、壊れたデータの救出と復元、
初回制御後のPWA更新、編集中の待機、オフライン時の応答を確認します。
GitHub Actions上での実際の公開は、導入時に別途確認してください。
