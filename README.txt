My Bookshelf PWA

■ ISBNカメラ読み取り・書誌情報の自動入力
「本を追加」または編集画面で「カメラでISBNを読む」を押します。
読み取り後に国立国会図書館サーチAPIで検索し、タイトル・著者・出版社・
日まで確定した刊行日を自動入力します。候補が複数あれば版を選択します。
ISBNを手入力して「ISBNで書誌検索」も利用できます。
既存の入力は保持し、置き換えたいときだけチェックを付けて再検索します。
読取・検索だけでは保存しません。内容を確認して「保存」を押してください。
映像は端末内で処理します。カメラは中止・画面を閉じる・非表示・60秒経過で停止します。
検索失敗時もISBNは残り、手入力できます。年月しか分からない刊行日は補完しません。
公開版での書誌検索には中継APIの導入が必要です。手順は proxy/README.md にあります。

■ ローカル起動（Node.js）
node scripts/prepare.cjs
node scripts/serve.cjs 8000
http://127.0.0.1:8000/ を開きます。ポート使用中は8001などを指定します。
CSSを分離したため、以前の簡易サーバーではなく上記のサーバーを使用してください。
ローカル表示は基準コミットIDと未コミット変更の有無です。
コード変更やコミット後は prepare.cjs を再実行してください。

■ 保存と同時編集
書籍は従来と同じ my-bookshelf-v1 キーにJSON配列で保存します。
既存の書籍形式を維持し、任意のcoverId（書影への参照）を追加しています。クラウド同期はありません。
複数画面での保存はWeb Locksで順番に処理し、編集開始時から保存データが
変更されていた場合は保存を止めます。入力は残るので必要な内容を控え、
編集を閉じて最新の本棚でやり直してください。削除・全件読み込みも同じ保護の対象です。
編集中以外は、別画面での変更や画面復帰時に本棚を読み直します。
Web Locksが使えない環境では安全のため保存を停止します。
HTTPSまたはlocalhost/127.0.0.1で、Web Locks対応ブラウザを使ってください。
旧版には同時保存の保護がないため、更新後は旧版のタブを閉じてください。

■ 読み込み失敗と復旧
保存データを読み込めない場合、専用の案内を表示し、蔵書数を「—」にします。
空の本棚として書き出さないよう、通常の書き出しと追加を停止します。
「元データを救出」は保存内容を加工せずTXTでダウンロードします。
救出ファイルは調査・修復用であり、そのまま読み込める正常なバックアップとは限りません。
ブラウザ自体が保存領域へのアクセスを拒否している場合、救出できません。
設定を確認して「再読み込みを試す」を使ってください。
正常なバックアップZIPまたは旧JSONを「読み込み」で選ぶと、確認後に全件置き換えます。
元データを救出してから復元してください。定期的な画像付きZIPの書き出しを推奨します。

■ PWA
HTTPS公開またはlocalhostで動作します。file://ではインストールできません。
ページ・CSS・JavaScript・アイコンをキャッシュします。
オンライン時はネットワークを優先し、失敗または約5秒経過でキャッシュを使います。
起動・画面復帰・オンライン復帰・表示中の1時間ごとに更新を確認します。
更新時は再読み込みしますが、編集画面や保存処理の完了を待ちます。

■ GitHub PagesでコミットIDを自動表示する公開方法
.github/workflows/pages.yml に公開ワークフローを用意しています。
今回の作業ではGitHub側の設定変更・commit・pushは行っていません。
導入時にリポジトリの Settings → Pages → Build and deployment の
Source を GitHub Actions に設定してください。
その後、mainへのpushまたはActionsの手動実行で、テスト→生成→公開します。
生成時に公開するコミットIDを埋め込み、キャッシュ名にも同じIDを使います。
公開ファイルはdistにまとめ、ソース側のバージョン表示を公開IDと誤認しないようにします。
ブランチから直接公開する方式では自動埋め込みは行われません。
公式手順: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

公開用生成（コミット済みの作業ツリー専用）:
node scripts/prepare.cjs --publish
未コミットのまま生成結果だけを確認する場合:
node scripts/prepare.cjs --preview
previewには開発版表示が入り、公開版のコミットIDとは区別されます。
distは生成物のためGit管理対象外です。公開時のキャッシュ番号の手動更新は不要です。

■ 自動チェック
node tests/regression.cjs
同時保存、古い画面からの削除・読み込み、保存失敗、壊れたデータの救出と復元、
初回制御後のPWA更新、編集中の待機、オフライン時の応答を確認します。
GitHub Actions上での実際の公開は、導入時に別途確認してください。

■ 書影・利用規約
書影は1冊につき1枚、Androidのカメラ撮影またはファイル選択で登録します。
外部APIからの書影取得や画像送信はありません。ISBNによる書誌検索は従来どおりです。
JPEG/PNG/WebPに対応。補正せず使う場合は縮小・再圧縮・切り抜きせず、Exifは向き（Orientation）だけを残します。
元のファイルは変更しません。GPS・撮影日時・機種・Exif内サムネイル等は保存するコピーから除きます。
表示は縦横比を維持します。HEIC/GIF/SVGは非対応です。
異常なファイルによるメモリ消費を抑えるため、1枚30MiB、6,000万画素を上限とします。
入力上限超過時はエラーにします。合計枚数は蔵書数と端末の空き容量に依存します。
初回利用時は規約本文、未選択のチェック欄、明示的な同意ボタンを表示します。
同意バージョンと日時はmy-bookshelf-termsに保存し、バックアップに含めません。
規約更新時はjs/terms.jsのversionを増やして再同意を求めます。

■ 画像保存とZIP
js/image-codec.js: Exif構造の検証・向きだけを残す処理（画素の再符号化なし）
js/images.js: IndexedDB my-bookshelf-images / imagesストアへのBlob保存
js/covers.js: 書影のプレビュー、選択、削除、本棚表示と一時URLの解放
js/backup.js: ZIPの書き出し・読み込み・欠損画像への対応
js/terms.js: 規約同意と初回画面の制御
ZIP v2はbookshelf.json（全書籍、画像対応表、形式バージョン）とimages/*を含みます。
暗号化はしません。画像合計200MiB、書籍JSON10MiBを上限とし、超過時は書き出しを中止します。
復元は全件置き換えです。書籍情報が不正な場合は中止し、現在のデータを維持します。
画像の欠損・破損時は警告し、確認後に該当画像なしで書籍情報を復元します。
旧JSONの読み込みも可能ですが、画像を含まないので書影は復元されません。
画像を新しいIDで先に保存し、次に書籍を確定します。確定までは旧画像を削除しません。
同じWeb Lock内で未参照画像を整理します。失敗で残った未参照画像は次の保存時に整理します。
書籍救出TXTには画像が含まれません。画像付きZIPとは用途が異なります。
IndexedDBの消失などで画像が見つからない場合は「画像なし」で書籍を表示します。
大量画像への性能最適化・保存領域永続化・暗号化は今回の範囲外です。

書影の自動テストも node tests/regression.cjs に含まれます。
実ブラウザ検証: 空の専用ポートで起動して /tests/browser-images.html を開きます。
生成画像の向き・画素一致、IndexedDB保存、ZIP往復、キャンセルを確認します。
検証用データは成功時に削除します。既存書籍がある環境では実行を拒否します。
Android実機でのカメラアプリ呼出し・端末の保存容量・インストール後の操作は別途確認してください。

■ 撮影直後の表紙補正
撮影画像は端末内で輪郭と四隅を検出し、傾き・台形のゆがみを補正した候補を表示します。
候補は自動保存しません。「この画像を使う」「四隅・縦横比を調整」「補正せず使う」
「撮り直す」「中止・キャンセル」から選べます。保存は最後に書籍の「保存」で確定します。
輪郭が不明瞭・写真の端に接する・候補が複数ある場合は手動調整へ案内します。
ファイル選択は従来どおり未加工でプレビューし、新しく選択した画像だけ「表紙を補正」を使えます。
保存済み画像を再補正する機能はありません。背景と区別しやすい場所で、表紙全体を写してください。
四隅の丸はドラッグまたは矢印キーで動かせます。横÷縦の比率は空欄で辺の長さから推定します。
本の実際の縦横比は写真だけでは確定しません。推定が不自然なら0.2〜5の範囲で指定します。
反射・隠れた部分・表紙の湾曲・色調は修復しません。文字の欠けや変形を採用前に確認してください。

js/cover-correction.js: 補正確認ダイアログ、一時画像、中止・手動四隅操作
js/cover-worker.js: 必要時だけ起動するWeb Worker。OffscreenCanvasで画像を処理
js/cover-geometry.js: 軽量な輪郭検出（Sobel・連結成分・凸包）、四点の透視変換
外部の画像処理APIやCDNにはアクセスしません。上記3ファイルをPWAキャッシュに同梱します。
大型の外部ライブラリは追加せず、画像処理を独立したモジュールとして実装しています。
補正用の作業画像は長辺2,048px以下、検出用は800px以下。出力は拡大せず長辺最大2,000px、
JPEG品質指定0.92で再符号化します。元写真の解像度・細部は補正画像に完全には残りません。
向きは読み込み時に画素へ反映し、出力Exifは引き継がないため二重回転しません。
一処理30秒で中止し、補正なしの採用を可能にします。中止・確定・ページ離脱時はWorkerを終了します。
端末内保存・ZIPには採用した画像1枚だけを含めます。補正前画像や四隅の情報は保存しません。
元の端末ファイルは変更しません。登録前の一時コピーは確定・キャンセルで破棄します。
既存書影は書籍保存が成功するまで保持され、ZIPの形式バージョン2は変更しません。

node tests/regression.cjs に検出・透視変換・不正な四隅のテストを追加しています。
実ブラウザでは空の専用ポートの /tests/browser-correction.html で、補正・未加工採用・
キャンセル・Exifの向き・保存とZIPが1画像のみであること・Worker失敗時の代替操作を検証できます。
Android実機での指による四隅調整、様々な背景・表紙での検出精度、処理時間は別途確認してください。
